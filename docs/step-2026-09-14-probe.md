# 新增：probe 下载前预检

**日期**：2026-09-14
**动机**：用户问「为什么每次想新下个漫画就会有问题」

---

## 一、问题的本质

连续三部 8comic 漫画都在首次下载时出问题，根因是三者叠加：

1. **站点随机化是设计使然**：章节脚本的变量名和字段位置都是随机混淆的，
   站点每次重新生成页面（哪怕只是更新一话）都会重排。
2. **失败是静默的**：布局认错不抛异常，只会生成指向不存在文件的地址，
   服务器回 404。问题要等实际下载时才暴露，且表现为「失败非常多」，看不出根因。
3. **验证样本太少**：前两轮我都只用手头那一部漫画验证，而每部漫画只是随机
   排列中的一个样本，用一个样本推出的规律必然在下一个样本上翻车。

前两条是站点的性质，改不了；第三条是方法问题，已在上一轮修复中纠正。
但**用户的体验痛点仍在**：开新漫画前无法预知能不能下。

## 二、解法

把「下到一半才发现错」提前成「几秒内就知道」。`probe` 走完整条链路：

    目录解析 → 数据串获取 → 布局识别 + 自检 → 抽样生成地址 → 实际请求验证

关键设计是**让服务器当裁判**。地址对不对，不靠比对历史快照（会因站点更新
过期而假阳性，上一轮就踩过），而是直接请求看是不是 200。

抽样取首、中、末三章，每章验首末两页。中间错位的话末页几乎必然也错，
所以首末两页足以暴露布局问题，代价只有 6 个请求。

## 三、实现

- `Site.diagnose(comic, session)`：站点特有的预检信息，基类默认返回空。
  8comic 覆盖它，报告认出来的布局、记录健全性、以及目录与数据的差异章节。
- `scraper.probe(...)`：通用流程，站点无关。
- `_reachable()`：`stream=True` 后立刻 close，只看响应头不下载正文。
- CLI 退出码：通过 0，不通过 1，方便 `probe && download` 串用。

## 四、验证

| 场景 | 结果 |
|---|---|
| 《入間同學》454 章 | ✓ 布局 pages(0) code(2) ch(42) sd(44) part(46)，退出码 0 |
| 《平行天堂》341 章 | ✓ 布局 sd(0) code(2) pages(42) ch(44) part(46)，退出码 0 |
| 《唐三葬》47 章 | ✓ 布局 ch(0) pages(2) code(4) sd(44) part(46)，退出码 0 |
| manwame（跨站点） | ✓ 39 章，无布局行，退出码 0 |
| 不支持的站点 | ✓ 报错并列出已支持站点，退出码 1 |
| 不存在的漫画 | ✓ 报错，退出码 1 |
| 布局认不出（打歪正则模拟） | ✓「记录里认不出「章节号」字段」 |

三部漫画三种不同布局都被正确识别并打印出来，直观印证了「位置不能假设」。

**一次自纠**：测「不存在的漫画」时我用了 `cmd \| tail` 取 `$?`，拿到的是
`tail` 的退出码 0，差点误报成 bug。去掉管道重测，真实退出码是 1，正确。
