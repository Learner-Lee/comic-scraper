# Plan：补齐缺失图片

**日期**：2026-10-19
**目标**：第 3 步加一个「检查并补齐缺图」按钮——联网取每章真实页数，和本地比对，
只补缺的那几张；已打包成 zip 的章节也要能补。

---

## 一、为什么需要它

现有的「人工检查」只显示本地张数，**不知道站点实际有多少张**，所以：

- 末尾缺图完全看不出来（序号连续，但就是少了最后一张）
- 打包之后源目录已删，更无从判断

实际踩过：早先有几章各缺 1 张（二次编码 bug 所致），是靠手工比对站点页数才发现的。
这个功能就是把那次的手工活固化下来。

而且用户现有 900 多章**全是 zip**，不支持 zip 的话这功能等于没用。

## 二、核心逻辑

```
对每个本地章节：
    站点真实图片列表 ← site.fetch_chapter_images(章节URL)
    本地已有序号     ← 目录里的 NNNN.* / zip 内的条目名
    缺口 = 期望(1..N) - 已有
    补下缺口对应的那几张（不重下整章）
```

**让站点当裁判**——本地有多少张不重要，和站点对不上才是问题。这与 `probe` 的
思路一致：历史记录会过期，服务器不会。

## 三、几个要害

### 3.1 本地章节 ↔ 站点章节怎么对应

本地目录名是 `{index:03d} {title}`。按 index 取 `chapters[index-1]`，
**再校验 title 是否一致**（经 `safe_name` 归一后比较）。

必须校验：站点若新增/删减了章节，index 会错位，那时补图会把 A 章的图写进 B 章——
比不补更糟。对不上就跳过并明确报告，绝不猜。

### 3.2 zip 怎么补

**不解包重打包，用追加模式**，且在副本上操作：

1. 把原 zip 复制成 `.part`
2. 在副本上以 `'a'` 模式追加缺的图
3. 校验副本（条目数 + 逐条 CRC）
4. 通过才 `os.replace` 覆盖原文件

这样全程不动原文件，中断或校验失败都只是丢掉 `.part`，原 zip 完好。
沿用项目既有的「原子落盘 + 校验后才替换」路子。

### 3.3 序号比对要忽略扩展名

本地文件名是 `0001.jpg` / `0001.webp`，补下来的扩展名由 Content-Type 决定，
可能和原有的不同。所以只按 4 位序号比对，不比扩展名。

### 3.4 请求量

每章要 1 次章节页请求才能知道页数：

| 站点 | 整部的请求数 |
|---|---|
| 8comic | **1 次**（数据串含全部章节，适配器已缓存） |
| manwame / manhuagui | 每章 1 次 |

454 章的漫画就是 454 次请求，慢且可能触发风控。所以：
- 保留 `-c` 参数，可只查指定章节
- 每章之间带 delay
- 日志实时输出进度，不让人干等

`Gap` 数据结构：章节名、序号、本地张数、站点张数、缺失序号、是否已打包。

## 五、验收标准

1. 对已 zip 的漫画能查出缺图并补齐，补完 zip 条目数与站点一致、CRC 通过
2. 故意从某 zip 删一张图，能被查出并补回
3. 故意从某目录删一张图，能被查出并补回
4. 章节 title 对不上时跳过并报告，不乱写
5. 全部完好时明确报告「无缺口」，不做无用功
6. CLI 与 WebUI 行为一致
7. 三个站点都能用（8comic 走缓存只 1 次请求）
8. 中断或校验失败不损坏原 zip
