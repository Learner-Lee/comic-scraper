## 阶段二：缺陷修复（已完成）

### P1-1　任务槽 TOCTOU 竞态

**改动**：`Job.try_begin(kind)` 在同一把锁内完成「判空闲 → reset → 置 running」；
`_start()` 改为返回布尔值，路由依据它决定 409。

**验证**：100 个线程用 `Barrier` 同时抢槽，**只有 1 个抢到**。

**连带改动**：删除 `Job.busy()`。它的职责已被 `try_begin` 完全吸收，且零调用者。
留着它不只是死代码，更是个陷阱——下一个人会照着它再写一遍
`if busy(): ... _start(...)` 的两步式竞态。

### P1-2　cancel 标志未受锁保护

**改动**：`self.cancel = False` → `threading.Event`，对外暴露 `cancel()` / `cancelled()`。
Event 自身线程安全，语义也更贴切（一次性信号）。类文档同步更正为
「除 _cancel 外，所有字段读写都在 _lock 保护下」。

**验证**：running 中置位 → `cancelled()` 为 True；任务结束后 `try_begin` 触发 reset，
新任务的标志自动清回 False。

### P2-1　CLI 章节范围报 traceback

**改动**：`parse_chapter_spec` 内部把解析失败转成带示例的 `ValueError`，
并新增两项校验：序号必须 ≥ 1、区间不得头尾反向。CLI 入口补捕 `ValueError`。
`app.py` 原本就捕获 `ValueError`，向后兼容，且现在会把具体原因透给前端。

**验证**：

| 输入 | 输出 |
|---|---|
| `abc` | `『abc』不是数字。格式示例：1-10,15` |
| `10-1` | `区间头尾反了：10-1` |
| `0-5` | `章节序号从 1 开始，不能是 0` |
| `1-` | `『1-』里有个数字漏了。格式示例：1-10,15` |

`python scraper.py download <url> -c abc` 现在输出单行 `参数错误: ...`，退出码 1，无堆栈。

### P2-2　WebUI 缺少选项

**改动**：
- 下载区新增「并发数」「间隔秒」输入框，placeholder 显示当前生效的默认值，留空即用默认
- 打包区新增 `.cbz` 勾选框
- 后端 `_opt_num()` 统一处理：留空或填错都退回默认值，并夹进合理区间（并发 1–16，间隔 0–5 秒）

**关键顺序**：参数校验一律排在抢槽之前。校验失败不该把正在跑的任务状态清掉。

## 未改动项及理由

- **取消只在章节边界生效**：要做到图片级中断需把取消信号传进线程池，
  复杂度不值当，且 UI 文案已明确告知「当前章节下完后停止」。
- **`JOB.zip_path` 字段名误导**（实际存的是漫画目录路径）：改名需同步动前端，收益低。

---

## 遗留的最大风险（非本次范围）

`scraper.py` 顶部的 AES 密钥、`[data-chapter-list]` 与 `.profile-text h1` 两个选择器
都是从站点扒的硬编码值，站点改版即全线失效。当前的缓解手段是**报错信息足够明确**
（不会静默失败），重新提取方法记在 README 的「维护提示」一节。
