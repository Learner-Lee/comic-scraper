# 修复（第二轮）：字段位置不能有任何假设

**日期**：2026-09-14
**触发**：下载《入間同學入魔了》(id 15059) 报「数据串里找不到第 1 章」

---

## 一、同一个错误，我犯了两次

上一轮修复时，我把 `sd` 和 `code` 改成了按语义识别，却把 `ch` 和 `pages`
留成了按位置取（`by_off.get(0)` 和 `by_off.get(2)`）。这次就栽在这里。

三部漫画的实际布局，五个字段的位置**完全是随机排列的**：

| 字段 | 《唐三葬》 | 《平行天堂》 | 《入間同學》 |
|---|---|---|---|
| `ch` | 0 | 0 | **42** |
| `pages` | 2 | 2 | **0** |
| `code` | 4 | 6 | 2 |
| `sd` | 44 | 4 | 44 |
| `part` | 46 | 46 | 46 |

《入間同學》的章节号在偏移 42，而我写死在 0，取到的是页数字段，
自然「找不到第 1 章」。

**教训**：修 bug 时只改了触发问题的那两个字段，没有把同类假设一次性清干净。
一个位置假设是 bug，五个位置假设就是五个待爆的雷。

## 二、还有一个隐蔽的正则 bug

`pages` 用 `ps\s*=\s*(\w+)` 提取，但页面里循环外先有一句 `var ps=0;`，
`search()` 取第一个匹配就拿到了字面量 `'0'`，查不到字段后**静默回退**到写死的
偏移 2——那里恰好是 code。

正则改成只认变量名开头（`[A-Za-z_$][\w$]*`）挡掉数字字面量，并且改为遍历
**全部**匹配、取第一个真正属于记录字段的。

## 三、修法：零位置假设 + 双重自检

五个字段全部按「脚本里怎么用它」来认：

| 字段 | 识别依据 |
|---|---|
| `ch` | 谁拿去和 `ch` 比较：`if(VAR==ch &&…` |
| `pages` | 谁被赋给 `ps` |
| `sd` | 谁被当图床号取头两位：`su(VAR,0,1)` |
| `code` | 谁按 `mm(j)` 取 3 字符 |
| `part` | 谁拿去和 `"0"` 比较 |

并加了两层自检，因为**布局认错不会当场失败，只会悄悄生成一堆 404**，
那是最难排查的一种失败：

1. **结构自检**：五个字段必须落在 47 字符记录内，且互不重叠
2. **数据自检**：第一条记录的图床号必须是两位以上数字、页数必须是 1–999 的整数

任何一层不过就明确报错，绝不拿猜的布局硬算。

## 四、关于「布局为什么会变」

连续抓同一页面三次，数据串和布局**完全一致**——不是每次请求随机化。

真相是：本轮验证中《平行天堂》的数据串从 16063 变成 16110 字符，正好多了
47 字符（一条记录），记录数 340→341。**站点更新了一话，重新生成页面时把
布局重排了**。所以布局按「漫画」算不是固定的，按「站点每次重新生成」才会变。

这也意味着：**上一轮记录的「已知正确值」会过期**，不能拿它当回归基准。

## 五、验证方法的修正

前两轮我用「和上次记录的 URL 逐字比对」当验收标准，这次它给出了假阳性
（报告《平行天堂》回归，其实是站点数据更新）。

改用**服务器实际响应**作裁判——生成的 URL 能不能下载，服务器说了算：

| 漫画 | 抽查章节 | 结果 |
|---|---|---|
| 唐三葬 (47 章) | 第 1 / 24 / 47 章 | 首末页全 HTTP 200 |
| 平行天堂 (341 章) | 第 1 / 171 / 8003(番外) 章 | 首末页全 HTTP 200 |
| 入間同學 (454 章) | 第 1 / 228 / 455 章 | 首末页全 HTTP 200 |

共 18 个地址全部 200。另实测下载《入間同學》前 3 章：44 / 30 / 21 张，
共 95 张真实 JPEG。

三部漫画的记录健全性检查（图床号是数字、页数合理）也全部零异常：
47 / 341 / 454 条记录无一异常。

## 六、留下的经验

1. **凡是从混淆脚本里认出来的东西，一个位置都不要假设**，全部按语义认。
2. **修同类 bug 要一次清干净**，只修触发的那个，剩下的迟早以同样方式爆。
3. **验收基准要选对**：拿历史快照比对会有假阳性，让服务器当裁判才靠谱。
4. **静默回退是危险的**：`fields.get(x) or 写死值` 这种写法把「认不出」
   变成了「悄悄用错的」，应该直接报错。
