## 一、manhuagui 的三层包装

这是三个站点里包装最厚的一个，但每层都是标准做法，没有站点私有的魔法值：

| 层 | 内容 | 踩点 |
|---|---|---|
| 1 | `eval` 写成 `window["\x65\x76\x61\x6c"](…)` | grep `eval` 搜不到，我第一次就这么漏掉了 |
| 2 | 标准 Dean Edwards packer（实测 `a=52, c=52`） | — |
| 3 | packer 的字典是 base64 调 `['\x73\x70\x6c\x69\x63']('\|')` | 解码是 `splic` 不是 `split`，实为 LZString 解压 |

解开后是 `SMH.reader({...})`，含 `bookName` / `chapterTitle` / `count` /
`images[]` / `sl{e,m}`。

**正确性有个现成的硬校验**：字典解压后 `split('|')` 的项数必须等于 packer
声明的 `count`。实测 52 == 52，是解对了的直接证据。程序里也保留了这条校验，
对不上就报错而不是硬算——这是从 8comic 那两轮教训里学来的。

## 二、自带 LZString 而不是装包

新增 `lzstring.py`，只实现 `decompressFromBase64` 一个方向，94 行。

不装 pip 包的理由：算法公开且固定，写一次就不会变；项目现在只有 4 个依赖，
为一个函数引入供应链风险不划算；而且正确性有上面那条「项数 == count」兜底。

## 三、一个容易漏的编码坑

首次实现时末图取回 404，URL 里是 `%25E5%25AE%25A3`——`%25` 是 `%` 的编码，
说明二次编码了。

查下来是：**同一条路径里混着两种编码状态**。章节目录名 `第01话` 是未编码的中文，
而有些文件名在站点数据里**已经是 `%E5%AE%A3…` 的编码形态**。

所以 `quote()` 必须把 `%` 放进 `safe`，让已编码的部分原样通过。修好后该章 8 页
全部 200。

## 四、站点清单

站点自己描述自己——`Site` 加了四个类属性（`label` / `url_hint` / `example` /
`notes`），一处填写，三处受益：

- `python scraper.py sites` 列出全部
- 贴错 URL 时，报错里直接带上清单（原先只印域名，看了也不知道该怎么贴）
- WebUI 第 1 步下方可折叠展开，贴 URL 前就能看到

以后加站点只要填这四个属性，清单会自动带上，不用再改别处。

## 六、三站脾气对照

| | manwame | 8comic | manhuagui |
|---|---|---|---|
| 图片数据 | AES-128-CBC | 定长记录 + 片段 | packer + LZString |
| 每章请求 | 1 次/章 | 1 次/整部 | 1 次/章 |
| 图床校验 Referer | 是 | 否 | 是 |
| 章节页校验 Referer | 否 | 是（否则伪装页） | 否 |
| 地址时效 | 无 | 无 | 有签名，会过期 |
| 图片格式 | webp | jpg | webp |
