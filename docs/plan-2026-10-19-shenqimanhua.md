# Plan：支持 shenqimanhua.net

**日期**：2026-10-19
**目标**：加入第四个站点「神奇漫画」，用法与现有三站一致。

---

## 一、实地调研结论（全部实测）

站点是 Next.js App Router。数据是**明文 JSON**，既不加密也不混淆——
这是四个站里最简单的一个，难点只在「数据藏在哪」。

### 1.1 目录页 `https://shenqimanhua.net/comic/<comicId>`

| 项 | 取法 |
|---|---|
| 漫画名 | `h1[itemProp="name"]` |
| 章节列表 | RSC 流数据里的转义 JSON |

**章节列表的三个来源，只有一个是全的**——这是本次最关键的发现：

| 来源 | 条数 | 能否用 |
|---|---|---|
| 可见 HTML 的 `a[href^="/read/"]` | 20 | ✗ 只是首屏，「展开更多章节」是 JS 按钮 |
| JSON-LD `hasPart` | 10 | ✗ 只有最近 10 话 |
| **RSC 流里的转义 JSON** | **142** | ✓ 完整 |

RSC 流中每章形如（注意是转义的）：

```
\"id\":\"cmiom81o81knwllnkjph4mrts\",\"title\":\"第1话\",\"number\":1,\"createdAt\":\"...\"
```

**`number` 不能当章节序号**：实测 106 / 114 / 123 各出现两次——「休刊公告」
和正式话共用了同一个 number。142 章 = 139 正式话 + 3 则休刊公告。

所以**按 RSC 流里的出现顺序编号**，那就是站点自己的阅读顺序（实测第1话在最前、
第139话在最后，无需反转）。

### 1.2 章节页 `https://shenqimanhua.net/read/<comicId>/<chapterId>`

图片路径同样在 RSC 流里：

```
\"url\":\"/image/crawl92hm/comicsRes/744/32155/img/1.webp\"
```

序号从 1 连续递增，拼上站点域名即可直接下载。

### 1.3 图片

| 项 | 实测 |
|---|---|
| 格式 | webp |
| 校验 Referer | **否**（带不带都是 200） |
| 时效签名 | 无 |
| 单图大小 | 约 500KB |

## 二、与现有三站对照

| | manwame | 8comic | manhuagui | shenqimanhua |
|---|---|---|---|---|
| 图片数据 | AES-128-CBC | 定长记录+片段 | packer+LZString | **明文 JSON** |
| 藏在哪 | `params` 变量 | 长字符串 | 三层包装 | **RSC 流** |
| 每章请求 | 1 次/章 | 1 次/整部 | 1 次/章 | 1 次/章 |
| 图床校验 Referer | 是 | 否 | 是 | 否 |
| 图片格式 | webp | jpg | webp | webp |

## 三、改动

只在 `sites.py` 加一个 `ShenqiSite` 并挂进 `_SITES`。通用流程、CLI、WebUI
一行都不用改——`sites` 清单、报错提示、WebUI 面板都会自动带上它。

填好四个自描述属性（`label` / `url_hint` / `example` / `notes`）。

## 四、稳健性要求

正则依赖 RSC 流的转义格式。站点若升级 Next.js 导致格式变化，必须**明确报错**
而不是静默返回空列表——这是从 8comic 那两轮教训里立下的规矩。

具体地：
- 目录页解析不到任何章节 → 报错并提示可能已改版
- 章节页解析不到图片 → 报错，不当成空章节跳过
- 不依赖 `number` 字段的唯一性（已证实会重复）

## 五、验收标准

1. `sites` 列出 4 个站点
2. `probe` 对该漫画通过，章节数 142
3. 章节顺序正确（第1话在前）
4. 下载前 2 章成功，文件是有效 webp
5. `check` / `pack` 照常工作
6. 现有三站不回归
7. 解析失败时明确报错
