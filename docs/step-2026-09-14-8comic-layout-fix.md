# 修复：8comic 记录布局写死导致大量下载失败

**日期**：2026-09-14
**触发**：下载《平行天堂》(id 14905) 时「失败非常多」

---

## 一、根因

字段偏移被写死成了某一部漫画的布局。**同一个站点，不同漫画页面的记录布局是不一样的**：

| 字段 | 《唐三葬》(12539) | 《平行天堂》(14905) |
|---|---|---|
| 图床号 `sd` | 偏移 44，长 2 | **偏移 4，长 2** |
| `code` | 偏移 4，长 40 | **偏移 6，长 40** |

首次实现时只见过《唐三葬》一部，就把它的布局当成了站点通则。对《平行天堂》来说
整体错位：从偏移 44 取到的其实是 code 的尾部字符，经 `lc()` 解码后得到
`-11`、`1742`、`-39` 这类负数和四位数（正常应是两位数字），拼出的 URL 自然全是 404。

**这个 bug 之所以没在上一轮被发现**：当时只用一部漫画验证，而那部恰好就是布局的来源。
单一样本验证不出「布局会变」这件事。

## 二、另一个错

记录条数原先取自页面的 `var chs`。《平行天堂》里 `chs=337`，但实际记录数是 **340**
（循环上限），目录则有 341 章。三个数字互不相同，`chs` 不是记录数。

## 三、修法

**不再猜位置，改为从页面内联脚本按语义现读布局**：

- 谁在 URL 里被当图床号用（`su(X, 0, 1)`）→ 那就是 `sd`
- 谁被当 code 用（`su(X, mm(j), 3)`）→ 那就是 `code`
- 谁被拿来和 `"0"` 比较 → 那就是 `part`
- 记录条数取自循环上限 `for(var i=0;i<N;i++)`

再回到循环体里查这些变量各自的偏移和长度。变量名是混淆的、位置是变的，
但**语义是稳定的**——URL 模板两部漫画完全一致。

认不出布局时**直接报错**，绝不用猜的布局硬算：那只会生成一堆 404，
比直接失败更难排查。`sd` 不是纯数字时也明确提示「多半是布局认错了」。

## 四、验证

| 项 | 结果 |
|---|---|
| 《唐三葬》不回归 | ✓ 首图与修改前已知正确值**逐字一致** |
| 《唐三葬》布局 | ✓ 自动认出 sd=(44,2) code=(4,40) |
| 《平行天堂》布局 | ✓ 自动认出 sd=(4,2) code=(6,40) |
| 记录健全性 | ✓ 两部漫画全部 47 / 340 条记录零异常 |
| 实际下载 | ✓ 1話 38/38、2話 18/18、3話 18/18 |
| 番外篇 | ✓ `ch=8001`/`8003` 正常（`lc()` 的 Z 分支产物） |
| 中段章节 | ✓ 第 170、337 話正常 |

**站点自身的数据缺口**：目录列了 341 章，数据串只有 340 条，第 338 話在站点数据里
确实不存在。程序会明确报错并跳过该章，不中断整轮。

## 五、教训

一个站点验证一部漫画是不够的。凡是「从页面扒出来的布局」，都要用**至少两个
不同来源**交叉验证，否则会把样本特例当成通则。
